# 지연 주입 학습 계획 — MDP 를 유지하는 행동 이력 증강 (2026-09-02)

실기 수조 세션(2026-09-02)이 배포 진동의 근본원인을 확정했다: **dead time
τ = 80 ms + 정책 포화(relay) → 2 Hz limit cycle** (brov_ros2
`docs/deadtime_result_to_training.md`). 학습 환경(IsaacLab)에는 이 지연이
구조적으로 없어(τ=0, phase margin +64° vs 실기 −24°) 정책이 높은 이득
(순항 Jacobian K_p ≈ 4.5, 실기 80 ms 문턱 3.52 의 128%)을 배웠다.

이 문서는 학습 측에서 그것을 고치는 **스펙**이다. 구현·학습·분석은 이 문서를
따른다.

---

## 1. 이론적 근거 — 왜 행동 이력이 MDP 를 복원하는가

### 1-1. 지연이 Markov 성을 깨는 기전

행동 지연 d 스텝이 있으면 시각 t 의 행동 `a_t` 는 `t+d` 에 플랜트에 닿는다.
전이는 `s_{t+1} = f(s_t, a_{t-d})` 가 되고, 관측이 `s_t` 뿐이면 정책은
**비행 중 행동** `a_{t-d}…a_{t-1}` 을 모른 채 결정해야 한다 — 같은 관측에서
최적 행동이 과거 행동에 따라 달라지므로 Markov 성이 깨진다(POMDP).

우리 16-D 관측 `[q_e, v_e^b, ω^b, z_v, z_q]` 는 전부 "지금 상태"다. `z_v`/`z_q`
는 과거 **오차**의 적분이지 과거 **행동**이 아니므로 이 격차를 못 메운다.
배포에서 관측된 실패가 정확히 이 기전이다: 명령 ①의 효과가 오기 전에 오차가
그대로라서 ②를 또 보냄 → 중첩 → 과보정 왕복 → 2 Hz.

### 1-2. 증강 등가 정리 (Katsikopoulos & Engelbrecht 2003; Walsh et al. 2008)

상수 지연 d 의 MDP 에서 정보 상태를

```
s̃_t = ( s_t, a_{t-d}, …, a_{t-1} )
```

로 증강하면 **지연 없는 MDP 와 등가**이고, 증강 공간의 최적 정책이 원문제의
최적이다. 관측 지연과 행동 지연은 에이전트 관점에서 등가다. 즉 관측에 최근
행동 d 개를 붙이면 문제가 다시 MDP 가 되고, 표준 RL 의 수렴 논거가 회복된다.

랜덤 지연 d ∈ {d_min…d_max} 에서는 이력 **d_max 개**면 충분하다 — 비행 중일
수 있는 모든 행동이 관측에 있으므로 (지연값 자체는 미관측이지만, 이력이 있으면
남는 불확실성은 "어느 것이 아직 비행 중인가" 뿐이라 robust-MDP 수준으로
좁아진다. 고정 d 라면 엄밀히 MDP).

### 1-3. 설계 세부의 이론적 이유

- **이력에 넣는 것은 "실행된 행동"이어야 한다** — 정책 평균이 아니라 탐색
  노이즈가 포함된, 환경에 실제로 전달된(clip 이후) 행동. 학습 중 실행 행동은
  평균과 다르며, 정리의 `a` 는 실행 행동이다. 관측 스택으로 대체할 수 없는
  이유이기도 하다(과거 관측에서 실행 행동은 역산 불가 — 노이즈를 모름).
- **이력 개수 = 지연 상한.** 지연을 정책 2스텝(80 ms)까지 랜덤화하므로 이력
  2개(12차원)로 충분. 지연 범위를 이보다 늘리면 이력도 늘려야 한다.
- **관측 신선도 jitter(15% 1스텝 지연 관측)는 의도적 소규모 POMDP 섭동**이다
  — 실측(attitude_age 15.1% 가 40~50 ms)의 재현이 목적이고, 표준 DR 관행.
  A/B 양쪽에 동일하게 걸어 비교를 오염시키지 않는다.

### 1-4. 주입값 — 이중 계상 보정 (중요)

실측 80 ms 는 명령→자이로 **전체**로 실기 액추에이터 응답을 포함한다. 학습
환경에는 이미 von Benzon 3차 추진기 동특성이 있고, 2 Hz 에서
`H(j·12.57)` = 이득 0.90, 위상 −15° ≈ **등가지연 21 ms** 를 이미 공급한다.
80 ms 를 통째로 얹으면 시뮬 총 지연 ~101 ms 로 ~26% 과잉이다.

**주입할 것은 전송 몫: 중심 60 ms** (= 80 − 21). 실기 분해(M4,
`LATENCY_DECOMPOSITION_PLAN.md`)가 끝나면 `τ_주입 = τ_total − τ_actuator,실기`
로 갱신한다.

### 1-5. 실증 전례 (검증된 인용만)

- Tan et al. RSS 2018 (arXiv:1804.10332) — 실측 지연을 시뮬에 모델링, Minitaur
  sim2real 성공 요인.
- Imai et al. 2021 (arXiv:2109.14549, MMDR) — 지연 **범위 랜덤화** → 실기
  +35~94%; **고정 지연 학습은 배포 분포가 다르면 급락**. 단 그 정책 관측에는
  prior actions 가 있었다 — 우리 설계 B 와 같은 계열이고, 이력 없는 A 의
  전례로는 못 쓴다.
- Schuitema et al. 2010 — memoryless + 지연 학습의 유일한 전례 (저차원).
- Sandha et al. 2021 — 60~100 ms 에서 NN 정책 급락, 지연 랜덤화 + 행동 이력
  (DMDP) 처방. **설계 B 가 이 처방의 완전형이다.**

## 2. 설계

### 공통 — 행동 지연 버퍼

- **물리 스텝(10 ms) 해상도의 링버퍼.** `_apply_action()` 이 버퍼 끝에서 꺼낸
  action 으로 추력을 계산한다. 정책 스텝(40 ms) 해상도로는 60 ms 를 표현할 수
  없다.
- **에피소드마다 지연을 uniform 랜덤**: **40~80 ms (물리 4~8 스텝)**, 중심
  60 ms. 에피소드 내 고정(실기 A2 의 r=0.809 가 "대체로 고정 + 약간의 jitter"
  를 시사; 스텝 내 jitter 는 아래 신선도 항이 대신한다).
- reset 시 버퍼는 0 (중립)으로 초기화 — 에피소드 시작에 유령 행동이 없어야
  한다.
- **기본값 off.** 기존 프로파일(`paper_ref_v1` 등)의 학습 결과가 1 bit 도
  변하면 안 된다 (회귀 확인 필수).

### 공통 — 관측 신선도 jitter

- 매 정책 스텝, env 별 확률 15% 로 **직전 스텝의 관측**을 대신 공급.
- 근거: 실기 attitude_age 분포 (15.1% 가 40~50 ms = 1 틱 묵음).

### 설계 A — 계약 유지 (ablation 대조군)

- 프로파일 `paper_delay_v1`: 관측 16-D 그대로 + 위 지연/신선도.
- 정책이 할 수 있는 적응은 이득 강하뿐(병진축) — 그것이 목표.

### 설계 B — MDP 유지 (본안)

- 프로파일 `paper_delay_hist_v1`: 관측 **28-D** =
  `[기존 16] + [a_{t-1} (6)] + [a_{t-2} (6)]`.
- `a` 는 **실행 행동** (탐색 노이즈 포함, `_pre_physics_step` 의 clip 이후,
  버퍼에 넣는 바로 그 값). reset 시 0.
- observation_contract 새 이름 (예: `brov_velocity_observation_v3_hist2`) —
  기존 16-D artifact 와 절대 혼용되지 않게 계약 검사로 막는다.
- 지연 상한 80 ms = 정책 2스텝 ⇒ 이력 2개로 §1-2 충족.

### 학습 매트릭스

| run | 프로파일 | obs | 지연 | 비고 |
|---|---|---|---|---|
| (기존) `fixplant_wa0017_s42` | paper_ref_v1 | 16 | 없음 | baseline, 재학습 불필요 |
| A | paper_delay_v1 | 16 | 40~80 ms | ablation |
| B | paper_delay_hist_v1 | 28 | 40~80 ms | **본안 (MDP 유지)** |

공통: seed 42, 2048 envs, 300 iter, `--rew_w_action 0.017`. Δa 벌점은 이번
매트릭스에 **넣지 않는다** — 지연 주입 단독 효과를 먼저 분리한다 (보상 압력
정량 ~8-9%/return 은 §6-보강 비판적 평가 참조).

## 3. 분석 프로토콜 (학습 후, 순서대로)

**단계 0 — 인과 사슬 검증 (가장 중요).** 평가 환경에 지연 80 ms 를 켜고
**baseline 정책**(fixplant_wa0017)을 velocity_hold [0.5,0,0] 로 돌린다.
예측: IsaacLab 에서도 ~2.4 Hz 진동이 재현되어야 한다 (위상 예산 계산과 실기
관측이 맞다면). 재현되면 주입 구현이 물리적으로 옳다는 검증이고, 안 되면
구현 또는 인과 설명에 구멍이 있는 것이므로 **여기서 멈추고 원인을 찾는다.**

**단계 1 — gate.** A, B 각각 velocity_hold [0.5,0,0]:
- 지연 **켠** 평가(40/60/80 ms 각각)와 **끈** 평가 모두.
- 지표: 추종률, `|ω|` 중앙/p90, action 포화율(|a|≥0.99), Fz 부호변화율,
  action PSD 지배 주파수 (기존 `--dump_log` + gate 분석 스크립트 계열).

**단계 2 — Jacobian.** 순항 관측점에서 autograd 로 K_p (= ∂a_i/∂v_e_i).
도구: scratchpad 의 `policy_ident.py` 방식 재사용. 판정 참조표:

| τ | 80 ms | 60 ms | 50 ms |
|---|---|---|---|
| K_p 문턱 | 3.52 | 4.40 | 5.01 |

- 예측 A: K_p 가 4.5 → 3 근처로 내려간다 (이득 강하가 유일한 적응).
- 예측 B: K_p 는 덜 내려가고, 대신 이력 성분에 유의미한 음의 Jacobian
  (∂a_i/∂a_hist,i < 0 — "이미 보냈으면 덜 민다")이 나타난다.
- B 에서 이력 Jacobian ≈ 0 이면 정책이 이력을 안 쓰는 것 — B 의 존재 이유가
  없어지므로 보고할 것.

**단계 3 — 비교표와 판정.**

| 판정 | 기준 |
|---|---|
| A 성공 | 지연 80 ms 평가에서 진동 없음(단계 0 대비 `|ω|` p90 1/5 이하, 포화 <10%) + 지연 0 평가 추종률 ≥ 95% |
| B 성공 | 위 + 추종률/RMSE 가 A 보다 우수 (이론상 B 가 성능-안정 트레이드에서 유리해야 함) |
| B>A 미달 | 이력이 학습되지 않은 것 — 이력 Jacobian 과 함께 보고, 원인 가설 제시 |

**단계 4 — 결과 기록.** 이 문서 하단에 결과 절 추가 + 수치 표. 배포 함의
(B 채택 시 계약 변경 목록: observation_node 이력 버퍼, policy_wrench_node,
metadata/계약 검사, export)는 결과가 나온 뒤 정리.

## 4. 구현 시 지켜야 할 것

- 기존 randomize()/DR 계약 관행을 따른다 (episode reset 훅에서 env_ids 단위).
- `paper_ref_v1` 무변화 회귀: 지연 기능 전부 off 일 때 기존 코드 경로와 동일
  해야 한다. 스모크로 확인 (짧은 iter 학습의 reward 곡선 비교면 충분).
- manifest 에 지연 파라미터(범위, 신선도 확률, 이력 개수) 기록 —
  export/재현성.
- 버퍼·이력·신선도는 전부 **환경 상태**이므로 reset 에서 초기화. 부분 reset
  (일부 env 만) 정확성에 주의.
- 순수 torch 단위시험 가능한 부분(링버퍼 지연 정확성, reset 초기화, 이력
  내용이 실행 행동과 일치)은 시험을 붙인다.

**스펙 범위 안에서 내린 구현 결정 2건** (§4 원칙에 따라 기록):

1. **신선도 hold 는 센서 블록(16-D)에만 건다.** 이력 6+6 은 센서가 아니라
   컨트롤러 자신의 발신 기록이라 배포측에서도 지연되지 않으며, 이력을 묵히면
   "지금 비행 중인 행동"이 관측에서 사라져 설계 B 가 복원하려는 MDP 자체가
   깨진다.
2. **묵은 틱에서는 z_v/z_q 적분도 멈춘다.** 배포측
   (`brov_base/observation.py`)의 stale/duplicate 표본 처리와 같은 규칙이고,
   `build_velocity_observation`의 기존 `integrate` 마스크를 그대로 쓴다.

지연 랜덤화는 연속 ms 를 반올림하지 않고 **정수 물리 스텝 {4,…,8} 균등**으로
뽑는다 — 반올림 방식은 양끝(40/80 ms)만 절반 무게가 되기 때문이다.

### 5-2. 단계 0 — 인과 사슬 검증 **재현 성공**

baseline(`fixplant_wa0017_s42/model_299.pt`, 지연 없이 학습)에 평가 시점에만
지연을 걸고 velocity_hold [0.5,0,0] 20 s.

| 주입 지연 | action/자이로 지배 주파수 | \|ω\| p90 [rad/s] | 포화율 | force clamp | 자세 진폭 |
|---|---|---|---|---|---|
| 0 ms | (없음, 12.5 Hz 수치잡음) | 0.0052 | 0.0% | 0.0% | ±0° |
| 40 ms | **3.12 Hz** | 2.726 | 100% | 100% | roll ±7° |
| 60 ms | **2.28 Hz** (yaw 2.35) | 3.454 | 100% | 99.6% | roll ±16° |
| 80 ms | **1.92 Hz** (pitch/heave 1.45) | 4.216 | 100% | 100% | roll ±22°, pitch ±22° |

zero-crossing 주파수와 FFT peak 가 소수점 둘째 자리까지 일치하는 깨끗한 relay
limit cycle 이고, 지연이 커질수록 주파수가 내려가고 진폭이 커지는 정확히
예상된 의존성을 보인다. **주입 구현은 물리적으로 옳다.**

**예측이 빗나간 지점 — 그리고 그 이유.** §3 은 "80 ms 를 켜면 ~2.4 Hz"를
예측했는데 실제로는 80 ms 에서 1.9 Hz, **60 ms 에서 2.28~2.35 Hz** 가 나왔다.
이것은 §1-4 자신이 이미 계산해 둔 이중 계상 보정과 정확히 일치한다: 학습
환경에는 von Benzon 3차 추진기 동특성이 이미 ~21 ms 등가지연을 공급하므로
실기 총 80 ms 를 재현하는 주입값은 60 ms 다. 즉 문서 §1-4(주입 60 ms)와
§3 단계 0(주입 80 ms, 2.4 Hz 기대)이 서로 어긋나 있었고, 실측이 §1-4 쪽을
지지한다:

- 주입 60 ms → 시뮬 총 ~81 ms → **2.28~2.35 Hz**
- 실기 총 80 ms → 실측 **2.0~2.3 Hz**, 위상 예산 예측 2.39 Hz

세 값이 겹친다. 단계 0 은 "지연이 진동의 원인"뿐 아니라 **"주입값은 80 이
아니라 60"이라는 §1-4 의 정량 주장까지** 독립적으로 검증했다.

부수 관찰: 모든 지연에서 surge 추종률은 100.0% 로 멀쩡하고 무너지는 것은
자세/각속도 루프다(roll/pitch/yaw action 이 ±0.9 rms 로 relay 포화). 실기에서
자이로에 2 Hz 가 보였던 것과 같은 그림이다.

- **예측 A (K_p 가 내려간다) — 맞음.** 7.23/6.46/6.14 → 2.62/2.98/1.91 (2.8~3.2배

- **예측 B (K_p 는 덜 내려가고 이력에 유의미한 음의 Jacobian) — 맞음.** B 의

- **다만 K_p 절대값 기준선이 스펙과 다르다.** §1 은 baseline 순항 K_p 를

  anchor 5.2~5.8 이다. 4.5 는 실기/Gazebo 기록 관측 분포 위에서(scratchpad
  `gain_vs_speed.py` 방식) 잰 값이고 이 표는 Isaac velocity_hold 순항점이라
  **관측 분포가 다르다**. 정책 간 비교는 같은 프로토콜로 했으니 유효하지만,
  "문턱 대비 %" 절대 수치를 실기 판정에 그대로 쓰면 안 된다.
- **B 에는 K_p 문턱 자체가 더 이상 적용되지 않는다.** 문턱표 3.52 는 memoryless
  비례 제어를 전제로 유도된 값인데 B 는 이력 되먹임으로 루프에 위상 앞섬을
  넣는다. 실제로 B 는 문턱의 128%인 K_p 를 갖고도 80 ms 에서 진동이 없다.

### 5-8. 예측 밖의 발견 — B 의 저지연 out-of-distribution 붕괴

**증상.** B 는 지연 0/20 ms 에서 7.7~9.2 Hz chatter 를 내고 action 이 23~26%
포화하며 force clamp 가 77~95% 발생한다(추종률 자체는 99.9~100%로 유지).

**해석.** B 의 이력 되먹임은 "비행 중인 행동"을 상쇄하는 예측항이다. 학습
분포가 40~80 ms 이므로 B 는 **항상 1~2 스텝이 비행 중**이라고 가정한 보정을
쓴다. 지연이 사라지면 상쇄할 대상이 없는데 상쇄를 계속하므로 −0.53~−1.08 의
음의 되먹임이 그대로 스텝간 진동원이 된다(주파수 7.7~9.2 Hz = 정책 25 Hz 의
1/3~1/2.7, 이력 길이 2~3 스텝 루프와 맞는 대역). A 는 이득 강하만 했으므로
저지연에서 그냥 보수적일 뿐 무너지지 않는다.

이것은 Imai et al. 2021 (MMDR)의 "고정/좁은 지연으로 학습하면 배포 분포가
다를 때 급락"의 정확한 사례이며, 우리 지연 범위(40~80)가 **0 을 포함하지
않는다는 점**에서 예견 가능한 결과였다. 스펙 §1-2 도 "이력 개수 = 지연 상한"만
논했지 하한은 논하지 않았다.

**처방(미실시, 다음 세션 후보).** 지연 범위 하한을 0 또는 10 ms 까지 내려
`action_delay_ms_range=(0, 80)` 으로 재학습하면 B 의 이력 보정이 "지연 크기에
따라 켜고 끄는" 형태로 학습될 여지가 있다(관측에 지연값 자체는 없지만 이력과
ω 의 관계에서 부분 추정 가능). 다만 배포 실기의 지연 하한이 40 ms 보다 훨씬
아래로 내려갈 근거가 아직 없으므로 **우선순위는 낮다** — 실기 M4 지연 분해
결과가 하한을 정하는 것이 순서다.

### 판정

- **포화 기준(<10%): 양 시험점 모두 통과 (0%).** relay limit cycle 은 양
  시험점에서 소멸 — baseline 이 떨던 그 조건이다.
- **진동대 RMS 기준(≤0.072): 원문 그대로는 미통과.** 직결에서 0.107~0.122
  (기준의 1.5~1.7배, baseline 대비 7~24배 개선), mavproxy 에서 sway 2.32 잔존.
  단 이 기준의 절대값 비교에는 결함이 있다 — 실기 0.36 은 0.25 m/s·leg 1 m
  조건이고 SITL 은 0.5 m/s·leg 5 m 라 여기(excitation)가 다르다. 환경 내
  비율로 보면 직결은 명백한 통과 수준이다.
- **mavproxy 의 sway 잔존은 비포화·유계 진동**(명령 40 N, relay 아님)이며
  직결에서 20배 작아진다 → **jitter 로 지속 가진되는 저감쇠 모드**로 해석.
  A 의 학습 분포(에피소드 내 고정 지연 + 15% 신선도)에 mavproxy 급 timing
  jitter 는 없다. 실기 링크는 r=0.809 로 직결(0.934) 쪽에 가깝고 mavproxy
  (0.487)는 비관적 극단이므로 실기 전망은 직결 결과가 더 대표적일 것으로
  보나, **실기 검증으로만 확정된다.**
- **부수 관찰**: 오래 미해결이던 SITL 속도 초과(+11~26%)가 A 직결에서
  98.2% 로 사라졌다 — 초과의 상당분이 진동 결합(정류 효과)이었을 가능성.
